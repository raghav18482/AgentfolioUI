# Agentfolio UI — Full Parity Port Plan

Porting the Jinja/vanilla-JS frontend at `MyFinancesMCP/frontend` (8,391 lines across
23 templates, 11 chart modules, 2 utils, 1,846-line stylesheet) to the React SPA at
`AgentfolioUI/src`.

**Status legend:** `[ ]` not started · `[~]` in progress · `[x]` done

---

## 0. Decisions

| Decision | Choice | Consequence |
|---|---|---|
| Charting | **ECharts for dense charts, Recharts stays for the simple ones already working** | New dep `echarts`; one `<EChart>` wrapper; the 11 existing option-builders port near-1:1. Two chart libs coexist — acceptable, revisit after parity. |
| Backend | **Add JSON endpoints, leave Jinja routes intact** | `MyFinancesMCP` gets ~6 new endpoints + 2 contract fixes. The old UI keeps working as a fallback through the whole port. |
| Hosting | **FastAPI serves the Vite build, same origin** | Session cookie works untouched, no CORS, no auth rework. Mounted at `/app` during the port, moved to `/` at cutover. |

## Implementation log

Verified in a browser against the **real FastAPI routers** via an offline harness
(`/tmp/agentfolio-verify/dev_server.py`: throwaway SQLite, fake broker with
deterministic candles, LLM/WhatsApp/NSE stubbed). Nothing touches the real DB,
Angel One or WhatsApp.

**Phases 1–3 — deviations from the plan above, and why**

- **No zustand auth store.** Session is server state, so it lives only in the
  react-query cache (`hooks/useSession.ts`). Logout clears the whole cache so the
  next user on the browser never sees the previous portfolio.
- **Option builders are written with their consuming page**, not all in Phase 1 —
  each lands verified rather than as untested dead code. `useEventSource` likewise
  moves to Phase 7.
- **Added** `ButtonLink` + `buttonStyles` (the landing page nested `<button>` inside
  `<a>`), `DataTable` (every page re-inlined the same table), `ChartCard` (uniform
  loading/error/empty at chart height), `InfoPopover`, `NotFoundPage`, route-level
  code splitting (main chunk 991 KB → 350 KB), and **Vitest** with fixtures
  generated by the legacy `ai-key.js`, proving both directions of key
  compatibility.
- **`Button` defaults to `type="button"`** — the risk form's Cancel button was
  implicitly a submit.
- **Backend addendum:** `/api/portfolio/analytics` never returned positions, orders
  or trades, so the React Positions and Orders pages were always empty. Added
  `GET /api/portfolio/{positions,orders,trades}` with the broker→row mapping moved
  into `web/view_models.py` and shared with the Jinja pages. **Positions and Orders
  pages were therefore pulled forward from Phase 6** (Sell Avg column, Executed
  Trades tab, Order ID column all done).
- **Where each legacy Analytics chart lives:** following the React app's existing
  structure, the Dashboard hosts the overview charts (P&L heatmap, gainers &
  losers, sector allocation, cash gauge, portfolio vs NIFTY 50); Analytics hosts
  per-stock and what-if tools (candlestick, prediction, rebalancer). Each legacy
  chart exists exactly once.
- **"Beta scatter" was a misnomer** in the legacy code: it is cumulative-return
  lines plus a stats bar (beta band, daily alpha, R², days, per-stock chips, an
  explainer per metric). Ported as such.
- **Sector allocation uses `data/sector_map.json`** like the legacy chart, not
  `/api/sectors/overview`, which drops ETF/Other holdings and triggers live NSE
  index fetches just to draw a pie.
- **Accuracy fixes in copy:** both footers claimed credentials are never stored,
  which stopped being true with enrollment. The Connect page's security list now
  scopes "never stored on disk" to credentials given to an MCP client.

**Phase 5 — Research**

- **Whole-page rewrite, six Recharts/legacy-shaped components deleted.** The old
  types (`FundamentalData`, `TechnicalData`) did not match the API at all; they now
  describe the real payloads, including the Python-computed `score`.
- **`chart_data.ohlc` is `[open, high, low, close]`**, not ECharts' order — the price
  chart reorders it. Tooltips read OHLC from the source array by `dataIndex`:
  ECharts' `params.data` for a candlestick *prepends the category index*, which
  shifted every field by one. Found in the browser; the same latent bug is fixed in
  `candlestick.ts` before Phase 4 builds on it.
- **Provisional (`confidence: low`) scores render grey**, with the confidence copy,
  the sector-adjustment note and the verbatim disclaimer.
- **AI summary** is a `useQuery` keyed by `(symbol, saved key)`, so a slow reply for
  a stock the user has left can never overwrite the one on screen. Regenerate sends
  `refresh: true` to bypass the server cache.
- **Glossary** (`/static/data/metric_glossary.json`) is one cached query shared with
  the future Learn page; each metric's ⓘ is the shared `InfoPopover`.
- Only the active tab is mounted, so charts always initialise at their real width
  (no hidden-tab resize workaround needed). `HoldingPills` is shared with Analytics.
- **AI summary uses the deployment's `OPENROUTER_API_KEY`, not the user's** (changed
  after review). The endpoint ignores any `api_key`/`model` in the body, answers 503
  if the server has no key, and rate-limits Regenerate to once a minute per stock
  because it now spends the deployment's credit. The Research page no longer asks
  for a key. Dashboard insights and Ask still use the user's own key. The legacy
  Jinja Research page still gates its summary on a stored key (it still works; the
  key is just ignored).
- **Learn page built early** (was Phase 9): `/learn`, login-gated like the legacy
  route, `lib/glossary.ts` (+ tests) for pillar order and band ranges, hash deep links
  from Research popovers (`/learn#pe_ratio`, `#how-it-works`).

**Phase 4 — Analytics**

- **Pure logic lives in `lib/`, with tests:** `lib/prediction.ts` (the engine label —
  heuristic is always "Rule-based score (no model)" — the calibration-notice rule and
  the 45/55 leaning band) and `lib/rebalance.ts` (simulation maths). Chart option
  builders import from `lib`, never from `features`.
- **Rebalancer: two legacy bugs fixed.** (1) Moving a slider after "Apply" silently
  threw away every reinvestment, because current value was recomputed from the
  original. Sells and buys are now separate state, so both survive. (2) Reinvestments
  were each checked against *total* freed cash, so several could overspend it; they are
  now checked against the cash still unspent. Added Reset and an inline error instead
  of silently ignoring a bad Apply. "Keep as Cash" is no longer a dropdown option (it
  did nothing) — unspent cash is shown as "Cash left to deploy" instead.
- **Rebalancer chart is plain React state → memoised option**, not imperative
  `setOption` as the plan suggested: twelve bars redraw instantly, so the extra
  machinery bought nothing. Animation is off so bars do not trail the slider.
- **`fetchPrediction` throws on `{error}`**: the server reports "not enough history"
  as HTTP 200. Added `useCandles` / `usePrediction` hooks; `LivePriceCard` now shares
  `useCandles` (same cache entry as the Analytics candlestick).
- The registered model's SHAP signals can have a null value; shown as "—" (legacy
  printed "null"). The old Recharts price/prediction views and the `CandleData` type
  are gone.

**Phase 7 — deviations and findings**

- **Backend bug fixed (pre-existing, production):** `POST /api/briefing/schedule`
  always failed with a 500 — `_next_run_utc_from_ist()` returned a naive datetime
  and the `schedules.next_run` column rejects naive values. Now returns aware UTC,
  like the scheduler's own writer. Regression test proven to fail on the old code.
- **Legacy candlestick bug fixed in the port:** ECharts wants `[open, close, low,
  high]`; both legacy candlestick charts passed the broker's `[open, high, low,
  close]`, so every candle drew the day's high as its close (almost all green) and
  the tooltip swapped C and H. `toCandleSeries()` reorders; unit-tested.
- **Proposals:** the server's `count` covers every status — the old React badge
  called it "pending". Approve returns 200 with `ok: false` when a risk or
  compliance check blocks the order; that is now reported as a failure, not
  success. Approval goes through a confirm dialog naming the order (was
  `window.confirm`). Poll interval 8 s, as legacy.
- **Risk form:** goal values are `"wealth creation"` (with a space), products field
  is `allowed_products`; all nine fields ported.
- **Chat:** `useAgentChat` + `components/chat/*` are shared with Phase 8. Saved
  threads are created on the first message, not on "New conversation", so history
  never fills with empty entries. "New conversation" sits in the chat column's
  header (it only affects the chat).
- **Live feed:** ticks go to the ECharts instance, not React state; "today" is the
  India date, not UTC (legacy used UTC, wrong between 00:00 and 05:30 IST).

## 1. Conventions this port must follow

Derived from the existing code — not invented. Every new file obeys these.

**Layering**
- `src/api/<domain>.ts` — thin async functions over the shared `axios` instance. One
  function per endpoint, returns typed data, no React, no state. Never call `axios`
  directly from a component.
- `src/types/index.ts` — single barrel of `export interface`, grouped by `// --- Domain ---`
  comment banners. No per-file types.
- `src/hooks/` — `useQuery`/`useMutation` wrappers and `zustand` stores. Query keys are
  arrays: `['portfolio']`, `['fundamental', symbol]`.
- `src/features/<domain>/<Thing>.tsx` — page components plus their co-located
  sub-components. One component per file, named export, `function` declaration (not
  arrow-const).
- `src/components/ui/` — presentational primitives only: `clsx` + a `variants` record +
  spread rest-props. No data fetching, no business logic.
- `src/components/layout/`, `components/auth/`, `components/chat/`, and new
  `components/charts/` for cross-feature composites.

**Styling**
- Tailwind v4, CSS-first. Tokens live in the `@theme` block in `src/index.css`. Use
  `surface-*` / `brand-*` / semantic `emerald|rose|amber` — never raw hex in JSX.
- Page shell is always `mx-auto max-w-7xl px-4 py-8 sm:px-6 space-y-6`.
- Headings: `font-display text-2xl font-bold text-white sm:text-3xl` + a
  `mt-1 text-sm text-surface-200/60` sub. This repeats 10× — extract `<PageHeader>`.
- Entry animation: `animate-fade-in` on the header, `animate-slide-up` on the first
  content block.
- Numeric cells: `tabular-nums`. P&L colour via `pnlColor()` from `utils/format`.

**Data**
- react-query for everything server-side. `staleTime: 60_000` default is already set in
  `main.tsx`; override per-query only where the old UI did (sectors 6h, breadth 5min).
- `zustand` for client-only state (auth, toasts, AI key).
- Mutations invalidate by query key, then `toast.success(...)`. Never refetch manually.

**Rules**
- Never `dangerouslySetInnerHTML`. LLM output goes through `<Markdown>`.
- `clsx` for every conditional class.
- Loading → `<Spinner size="lg" />`. Error → an `<Alert variant="error">`. Empty →
  `<EmptyState>`. All three states handled on every data surface.

## 2. Phase 0 — Backend JSON surface + SPA hosting  ✅ done

Repo: `MyFinancesMCP`. **Blocks everything else** — login is currently broken against
this backend, so do this first.

### 2.1 As built

- `[x] web/auth_flow.py` **(new)** — `login()`, `enroll()`, `logout()` and
  `AuthFlowError(message, status_code, field?, retry_after_sec?)`. The Jinja form
  handlers in `web/routers/auth.py` now call these too, so throttling, the single vague
  401 message and verify-broker-before-DB-write exist exactly once. Lives beside
  `web/dependencies.py` because routers may not import each other.
- `[x] web/routers/auth_api.py` **(new)**
  - `GET /api/auth/config` → `{countries, default_dial_code, min_password_chars}`
  - `POST /api/auth/login` → `200 {ok, client_id}` · `400 {error, field}` bad number ·
    `401 {error}` no match (identical text for unknown number and wrong password) ·
    `429 {error}` + `Retry-After` · `502 {error}` broker rejected stored creds
  - `POST /api/auth/enroll` → `200 {ok, client_id}` · `400 {error, field}` ·
    `409 {error, field: "whatsapp_number"}` number owned by another account
  - `POST /api/auth/logout` → `{ok: true}`
- `[x] web/routers/session.py` **(new)** — `GET /api/session/bootstrap` →
  `{authenticated: false}` or `{authenticated, client_id, premium: {registered,
  whatsapp_number}}`, `Cache-Control: no-store`. Anonymous is a 200, not a 401.
- `[x] GET /api/feedback/token` → `{token}` (`no-store`); `503` if `ENCRYPTION_KEY` is
  unusable.
- `[x] POST /api/premium/register` additionally accepts `{country_code,
  whatsapp_number}` and normalises through the same function enrollment uses. The
  legacy `{whatsapp_number: "+91…"}` shape still works.
- `[x] web/app.py` — `SinglePageApp` static mount at `SPA_MOUNT_PATH = "/app"` when
  `SPA_DIST_DIR` points at a build with an `index.html`; registered last so it can never
  shadow an API route. Deep links get the shell (`no-cache`), `assets/*` get
  `immutable`, missing files with an extension still 404.
- `[x] tests/test_spa_api.py` **(new, 17 tests)**; `tests/test_app_wiring.py`
  registry updated. Existing suites unchanged and green.

### 2.2 Deviations from the original plan, and why

| Planned | Built | Why |
|---|---|---|
| `StaticFiles(html=True)` for deep links | `SinglePageApp` subclass | `html=True` only maps directories to `index.html` and misses to `404.html` — `/app/dashboard` on refresh would 404. |
| `GET /api/meta/countries` | `GET /api/auth/config` | It also carries `min_password_chars`; it is auth-form config, not country metadata. |
| `server_url`, `has_risk_profile`, `min_password_chars` in bootstrap | dropped | `server_url` → `window.location.origin` (correct behind a TLS proxy, where `request.base_url` says `http://`); risk profile already has `GET /api/trading/profile`; password rule lives in `/api/auth/config`. |
| Rate-limit the feedback token mint | no limit | Anyone can already mint by loading `/`; the per-IP cap on submissions is what bounds a token's value. |
| `time_ist` on the briefing schedule | no backend change | The Jinja UI already derives it from `next_run` with `Intl` and `timeZone: "Asia/Kolkata"`; the SPA does the same. |
| Bootstrap is "cheap and DB-only" | cheap in steady state | When the in-memory broker session has expired, `current_client()` rebuilds it — one broker login, the same cost the first Jinja page load pays. |

### 2.3 Findings that affect later phases

- `build_profile_from_dict` accepts goal `"wealth creation"` (space, not underscore) and
  the products field is `allowed_products`. The current React risk form sends
  `wealth_creation`, so the server rejects it today. → Phase 7.
- Since the auth-flow change every enrolled user has an active `users` row, so every
  logged-in user is already "premium registered". The activation form is now only
  reachable if a row is deactivated mid-session. Ported for parity anyway. → Phase 7.
- `DELETE /api/briefing/schedule` only disables the row; `GET` then returns
  `{exists: true, schedule: {enabled: false}}` → the UI shows PAUSED, not "no schedule".

## 14. Risks

| Risk | Mitigation |
|---|---|
| **AI key breaks for existing users.** Changing the localStorage key, envelope version or KDF params silently invalidates saved keys. | Port `lib/crypto.ts` byte-for-byte; keep `mfmcp_ai_key` / `mfmcp_ai_model` and `v:1`/`v:2`. Verify by saving a key in the Jinja UI and reading it in the SPA. |
| **Bundle size** — two chart libraries. | `echarts/core` with explicit registration; Phase 4 left Recharts with no consumers, so it was uninstalled. |
| **Live-tick re-render storms.** | Ticks go to the ECharts instance via ref, never through `setState`. |
| **Broker calls on the auth path.** `/api/portfolio/analytics` as an auth probe can take seconds and hits Angel One. | `bootstrap` is cheap and DB-only. |
| **Premium 403s shown as errors.** Several endpoints return 403 for free users; that's expected state, not failure. | `<PremiumGate>` branches before the query runs. |
| **Disclaimer drift.** The Responsible-AI text, the enroll trade-off warning and the prediction engine label are compliance-adjacent. | Port verbatim; no rewording during the port. |
| **Jinja/SPA divergence during the port.** Two UIs, one backend. | New endpoints are additive; Jinja routes untouched until Phase 10. |
